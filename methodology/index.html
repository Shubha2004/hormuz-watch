Data sources & methodology

This page documents how data reaches the dashboard, how its quality is labelled, and the hard limits of what this demonstration build can tell you.

Our data-integrity commitment

  • Never fabricate. Every datum carries a quality level; simulated demonstration values are never presented as observations.
  • Label everything. Each panel shows a DEMO badge naming its quality level and a source line with provenance and last-updated timestamp.
  • Distinguish quality levels. Live, historical, estimate and simulated data are visually and semantically distinct throughout the site.
  • Attribute sources. Every section cites where its data came from, so you can judge how much trust it deserves.

Data quality taxonomy

Four quality levels are used across the dashboard. The badge next to every panel tells you which one applies.

Level Meaning Badge
LIVE An observation fetched from a public source moments before display. Emerald badge with a pulsing dot.
HISTORICAL A recorded fact from an archive — true for its time, not for now. Sky-blue badge.
ESTIMATE A model-based approximation. Directionally useful; not a measurement. Amber badge.
SIMULATED Invented demonstration data bundled with the app. Not real. Amber badge.

Provider architecture

All data flows through a single provider layer (loadMarketData()) that assembles one MarketData object every UI component consumes. By default it serves the bundled demonstration dataset, with every section carrying a SIMULATED or ESTIMATE quality badge.

The provider then attempts keyless live sources — currently the GDELT 2.1 news API — before display. Any failure (network error, malformed payload, disabled flag, timeout) falls back gracefully to the bundled demo items for that section, and the UI keeps its DEMO badge. A section is only labelled LIVE when a provider returned validated data. External responses are validated against a schema before use, and the provider never throws: the worst case is the full demo dataset.

Keyed providers — such as EIA for energy prices or commercial AIS vendors for vessel positions — are intentionally not called from the browser. They are documented in .env.example for a future server-side deployment, where API keys can be kept out of client-side JavaScript.

Environment variables

From .env.example. Only variables prefixed PUBLIC_ are exposed to the browser — secrets must never use that prefix.

Variable Default Purpose
PUBLIC_DEMO_MODE true Master switch: when true, all panels render demo data with a DEMO badge even if a live provider is configured.
PUBLIC_GDELT_ENABLED true Attempt the keyless GDELT news API before falling back to bundled demo headlines.
PUBLIC_MAP_TILES_URL CARTO dark Tile URL template for the Leaflet map; defaults to the free CARTO dark basemap (attribution required).
EIA_API_KEY (unset) Server-side only. US Energy Information Administration key for real energy price data — never expose in the browser.
MARINETRAFFIC_API_KEY (unset) Server-side only. Commercial AIS vendor key for real vessel positions — never expose in the browser.

Limitations

  • No real-time AIS feed is connected — vessel positions on this build are fictional.
  • Oil and market price series are simulated for demonstration; they do not track real markets.
  • Timeline entries are illustrative fictional scenarios, not real events.
  • Regional impact figures are exposure estimates, not predictions of disruption.
  • Insurance figures are illustrative estimates, never quotes or advice.
  • This site is not for trading, investment, navigation or safety-critical decisions.
